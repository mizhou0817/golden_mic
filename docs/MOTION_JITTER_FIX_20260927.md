# 自动推近导致画面抖动：根因与修复（2026-09-27）

## 根因证据

1. 原作品保存的 `motion_effects=true`、`motion_zoom_ratio=0.08`；[原任务日志](../data/tasks/064939d545964a2393c71ff40bab553d/task.log)确认 20 个片段均使用旧滤镜。开始修改前，当前渲染、流水线、媒体适配三份源码 SHA-256 均与原任务清单相同。
2. 旧链路是先放大到 2560×1440，再由 `zoompan` 逐帧计算中心裁切，最后输出 1920×1080。FFmpeg 将裁切宽高截为整数，并将 YUV420P 的裁切原点向下对齐到偶数像素。宽高与原点的取整并不同步；2 像素工作画布步进映射到 1080p 仍约 1.5 像素，并非原注释宣称的“无抖动”。
3. 完全静止的中心标记经过旧滤镜，90 帧内中心横/纵跨度约 1.684 / 1.689px，最大相邻帧中心位移 1.491px；关闭运镜和仅调色均为 0。新滤镜相同实验的中心跨度、相邻位移均为 0。颜色、片源运动、播放器和编码时间戳都不是这个受控实验的变量。
4. 原成片是逐行 30fps、1854 帧，所有段落都使用 `d=1`；不是漏设 `d=1` 造成重复输入帧。修复保留现有帧率与时间轴，没有插帧或变速。

实现依据：[FFmpeg zoompan 源码](https://ffmpeg.org/doxygen/trunk/vf__zoompan_8c_source.html)、[FFmpeg perspective 源码](https://ffmpeg.org/doxygen/trunk/vf__perspective_8c_source.html)。另外在本机 FFmpeg 9.0.2 实际运行并验证了坐标和时间行为，不只依据文档推测。

## 修复范围

- [backend/rendering.py](../backend/rendering.py)：`_ken_burns_filter()` 使用 `perspective` 的逐帧三次插值，浮点中心矩形以 1/256 源像素精度采样；运镜期间使用 YUV444P，最终再转换为 YUV420P。移除额外的 2560×1440 工作画布。
- `perspective` 的帧计数与旧滤镜不同，使用 `on-1`，保证首帧无裁切、末帧达到指定推近比例，之后不继续放大。关闭运镜、零缩放的原滤镜路径不变；每段仍保留原切点和显式定格补帧。
- [backend/readiness.py](../backend/readiness.py)：预检要求 `perspective` 能力，缺失时在启动阶段明确失败。
- [backend/provenance.py](../backend/provenance.py)：实现版本为 `2026.09.27.1`，把启动能力实现也纳入来源哈希。
- 普通制作和新换镜片段共用修复后的渲染函数。已有片段不会被静默改写；复用旧片段的重剪仍会复用原像素，不能把“重新混音”当成运镜修复。
