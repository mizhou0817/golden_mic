# 运行维护手册

[项目首页](../README.md) · [文档目录](README.md) · [快速开始](QUICKSTART.md) · [配置说明](CONFIGURATION.md) · [故障排查](TROUBLESHOOTING.md) · [使用指南](USER_GUIDE.md)

本页用于日常检查、空闲停机、备份和恢复，不是测试执行手册。安装见[快速开始](QUICKSTART.md)，测试隔离见[开发指南](DEVELOPMENT.md)，正式服务器发布见[部署说明](../deploy/README.md)。这里的流程不代表已经替你运行，也不授权新增付费调用。

## 1. 启动前确认

1. 明确本次服务、端口、任务目录及操作者；不要接管归属不明的监听进程。普通本地使用只绑定回环地址，生产保持 Nginx 前置、Uvicorn 单 worker。
2. 对照[配置说明](CONFIGURATION.md)确认使用开发还是生产模板。两模板覆盖 138 个字段，但生产占位符、私有模型和审批仍需操作者补齐。
3. 确认前端构建、字体、FFmpeg/ffprobe、目录权限和磁盘余量。使用[现有启动任务](../.vscode/tasks.json)或部署流程，不从历史报告复制 PID、版本化安装路径或过期制品地址。
4. 明确云服务和素材权限、额度。默认链路可能发送稿件、抽取音频和画面等输入给 Kimi/火山引擎；本地运行不是全离线处理。

**预检并非只读：** [预检入口](../backend/preflight.py)会读取配置、检查构建/字体、创建数据与启用的缓存目录，在任务目录写入并移除检查文件，并调用 FFmpeg/ffprobe 能力检查。必需模型包模式还会核对本地模型清单和摘要。提供方检查只验证配置前提，不验证真实凭证、连通性、额度或推理质量。

**正常启动也可能写数据：** [应用启动流程](../backend/main.py)会恢复本服务任务、处理未完成发布的本地回滚并启动到期清理。中断的生成不会自动续跑，可能恢复为失败。不要把启动应用当成无副作用的历史数据查看器；它不会自动下载模型或开始新的模型生成。

## 2. 看懂健康状态

| 入口 | 如何解读 |
|---|---|
| `/health/live` | 返回 200 只表示进程能响应，不表示可接单 |
| `/health/ready` | 200 表示启动检查通过且当前没有排空/磁盘问题；503 表示未就绪 |
| `/api/config/availability` | 浏览器安全摘要；必须检查正文 `status=ready` 或 `not_ready`，不能只看 HTTP 200 |
| `/api/config/limits` | 界面使用的限额/维护状态；不是提供方额度证明 |

就绪状态由**启动预检快照 + 当前排空/磁盘状态**组成，不会每次请求都重查依赖、模型或密钥。修改环境、依赖、模型配置后必须排空并重启；即使重启后 ready，也不等于真实语音或生产验收通过。

开发 Uvicorn 可在预检未通过时继续提供界面；现有 VS Code 启动任务会因预检失败退出，生产启动同样要求通过。不能用“界面能打开”代替就绪结论。具体失败项见[故障排查](TROUBLESHOOTING.md)。

## 3. 空闲停机和配置更新

**先排空，再确认空闲，最后只停自己的服务。** 排空是停止接收新工作并等待已接收工作结束，不是删除任务。

1. 通知使用者停止提交与上传，等待现有上传结束；确认自己有维护权限。
2. 由操作者在服务器本机按[部署流程](../deploy/README.md)启用排空。当前管理接口为 `/api/admin/drain`：POST 开始、GET 查看、DELETE 取消；仅供受保护的本机维护，不应通过公网代理暴露。
3. 检查运行快照：`queued_tasks`、`running_tasks`、`studio_jobs`、`task_operations`、`deleting_tasks`，以及汇总 `active_tasks` 都应为 0。快照不是上传监控；仍须单独确认没有上传或其他维护写入，并在停机前再次核对。
4. 通过启动该服务的终端或服务管理器正常停止，等待进程退出。只操作本次确认归属的实例，不能按端口或进程名批量终止、照抄旧 PID，也不能杀掉其他人的服务。
5. 停机后按需备份，再更新获准的配置/制品。重启后核对实际服务版本、live、ready 和原任务状态；不要通过新建付费任务来探测健康。

排空时 ready 返回 503 是预期行为。超时或中断应保留失败事实和待处理任务，不要假装正常停机。突然关机/强制结束不能视为完成优雅退出；重启不会自动补偿付费结果。

## 4. 数据保留和备份

| 数据 | 保留规则 |
|---|---|
| V2 草稿 | 24 小时空闲到期，服务端有效修改会影响草稿时钟 |
| V2 终态任务（含失败） | 72 小时；保留基准优先为处理结束时间，缺失时回退更新时间/创建时间 |
| 暂存上传 | 从创建起最长 72 小时；不能靠草稿续期无限延长 |
| 旧本地任务 | 开发模板 `TASK_TTL_HOURS=0` 关闭旧链路自动 TTL 清理；不控制 V2 |
| 删除/到期标记 | 墓碑保留 30 天用于解释不可用状态，不等于仍保有媒体 |
| 接收预算账本 | 取消、删除和失败不退还已接收次数；不是随任务一起可清空的缓存 |

到期时间与后台实际回收时刻可能不同；界面列出作品、浏览器保存草稿或持有链接，都不等于服务器仍保留文件。**不要调整旧任务的 `TASK_TTL_HOURS` 来修复 V2 到期。** 查看、确认或导出不是无限续期机制。

备份应由操作者在排空、停止写入后进行：

- 保存完整且一致的本服务任务存储，包括素材、不可变版本、任务元数据和 V2 接收账本；不要只复制成片后宣称可恢复编辑。
- 活跃 SQLite 不能只拷主数据库而忽略尚未落盘的 WAL；使用一致性备份方法或确认服务已完全停止。此页不提供批量删除/重置命令。
- 实际配置与秘密单独加密保管、限制访问，不放进源码、发布包或公共备份；模型清单/获批权重按许可独立保存。
- 浏览器访问凭证与服务端备份不是同一份数据。清空站点存储、切换 Origin/浏览器或轮换会话密钥可能影响访问；不要为了排错先清缓存。
- 保留失败记录和历史证据。恢复先在隔离位置制定方案，核对版本、目录、权限与保留策略，不直接覆盖运行中的任务，也不自动迁移或清空退役数据库。

备份恢复可能触发启动恢复/到期清理；必须先确认原到期时间，不能承诺恢复备份就延长访问期。需要长久保存的获准成片应在有效期内通过正常导出流程另行保管。

## 5. 访问凭证、能力和重试边界

- 当前产品无课堂/账号登录流程，但**无登录不等于无访问控制**。生产使用匿名签名会话、CSRF、Origin 和任务 capability（访问凭证），没有公开全局任务索引。
- 开发本地特权只适用于非生产、直接回环、回环 Host 且没有转发头的请求；同源代理不自动获得 `local_history`。显式错误/冲突凭证不会回退成放行。
- 保持 Uvicorn `--no-access-log`，并避免代理记录带查询参数的媒体 URL。不要粘贴 capability、Cookie、CSRF、完整下载链接或 Range 请求鉴权头；也不公开原始日志、堆栈、稿件或素材。
- V2 等待容量 50、旧 pending 5、处理并发 1、会话/IP/全站预算分别生效。排队空位不是免费调用额度，不多开 worker、不轮换身份、不删账本解限。
- `retrySame` 需服务端核对相同输入、实现/模型绑定和已完成提供方回执。网络中断或未知付费结果先读回状态并人工核对，不能自动重放；旧链路重试另有规则。
- 发布/导出独立检查当前版本和质量。生产模板保留 `QUALITY_GATE_MODE=block`；Settings 接受 `warn` 不意味着硬门禁解除，也不能手改报告、摘要或不可变版本让导出通过。
- 本地语音的 required/license 开关默认 false；生产模板 required=true 且 license=false。必须供应并批准模型、依赖和精确清单后才可能就绪，不能自动下载、借用测试绕过或关闭门禁假装完成。详见[配置说明](CONFIGURATION.md)。
